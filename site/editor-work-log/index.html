1The brief

SSL Studio is a desktop IDE for STARLIMS SSL. Its code editor is Monaco, the editor inside VS Code, and its Markdown editor is CodeMirror. Everything it knows about SSL comes from one place, the starlims-lsp language server. The IDE writes no SSL parser, tokenizer or formatter of its own.

The ask was plain: make editing feel like VS Code with IntelliSense, with Sublime Text's keys. One thing was explicitly out of scope. There would be no Copilot-style ghost text: AI while editing should be something you ask for on purpose, and AI integrations are a later project.

The work went in rounds. Each started with an adversarial review, trying to break the editor the way a developer would by accident. The findings were fixed and the fixes checked before the next round began.

2How the work was done

  • Real keys in a throwaway instance. Every review ran in an isolated copy of the app on its own port, with its own state folders and a scratch copy of the example project, so nothing typed could touch real work.
  • Server or client? Before calling anything a language-server gap, the same request went to starlims-lsp 0.32.0 directly over standard input and output, sent the way a full client sends it. That check overturned several early conclusions.
  • Look at it, at two widths and in two themes. Every visible change was looked at in the running app, 720 and 1400 pixels wide, light and dark, as the project's rules require.
  • Desktop self-tests on two systems. Three self-tests drive the real desktop window on Linux: a plain run, a close-and-restore run, and a long cycle. The same three, with the unit suite, run in a Windows 11 virtual machine on the same computer.

3Five everyday defects

The first review typed into the code editor the way a developer does. Five defects needed nothing from the server:

  • The doubled colon. Typing :wh and taking :WHILE from the list left ::WHILE. Punctuation typed just before a word is now replaced along with it when the chosen text opens with that punctuation.
  • Format on save stole the undo. The formatter's edit over a whole procedure joined the last words typed, so one undo removed both. The edit is now made as the smallest changes that give the same text, as an undo step of its own, and the cursor stays on its line.
  • Ctrl+M was a trap. It was the editor's "Tab moves focus" toggle. Pressed by accident, Tab left the editor instead of indenting, with nothing on screen to say so. It now jumps to the matching bracket, as in Sublime Text.
  • Unsaved scripts were second-class. A script with no file yet got no completion, diagnostics or outline. The server reads an untitled: document as it reads a file; only the client had held it back.
  • New scripts were indented with spaces under a house style of tabs. A script with no indentation yet now takes the house style's.

4Sublime Text's keys, without losing VS Code's shell ADR 0034

The project's design precedents name VS Code for the IDE's shell and Sublime Text for editing keys. Monaco came with VS Code's keys, and the shell had taken three of Sublime Text's for itself: Ctrl+Shift+D opened the Docs panel and Ctrl+J the bottom panel. The rule that settled it: while a text editor has the keyboard, a key that edits text does what it does in Sublime Text. Everywhere else, the shell's keys are VS Code's.

Ctrl+Shift+D
Duplicate the line or selection
Ctrl+J
Join lines
Ctrl+Shift+↑ / ↓
Move a line
Ctrl+Shift+L
Split a selection into lines
Alt+F3
Select every occurrence
F9
Sort lines
Ctrl+K Ctrl+U / L
Upper and lower case
Ctrl+Shift+M
Select to the bracket
Ctrl+R, Ctrl+Shift+R
Go to a symbol, in the file or the workspace
Alt+-, Alt+Shift+-
Go back and forward

Two-key shortcuts had never worked. The shell read one key at a time and took the second press for itself: Ctrl+K Ctrl+0 focused the side panel instead of unfolding. Now the second press reaches the editor. A setting swaps Ctrl+click and Alt+click between adding a cursor and going to a definition, as VS Code allows.

5Completion that knows what set it off

Before

After oMail: the list held the whole language: every keyword, function, class and snippet, some 520 names, the same anywhere in a script.

After

The members of Email alone, narrowed by what follows. After : at the start of a statement, the keywords alone. Nothing after a variable of unknown class.

This had first been put down to the server. It was the client's fault. The protocol lets a client say what set off a completion request: typing, a trigger character such as :, or a list that was not complete. The app never said, and never declared that it could. Told the trigger, the server answers precisely, including the range each keyword replaces.

Lesson

Ask the server the way a real client would before you blame it. A request sent without its context gets a generic answer, and that answer looks like a server limitation.

6Editing that is right for SSL

Toggling a comment ADR 0035

An SSL comment is /* … ;: it ends at the first semicolon, and every statement ends with one too. Monaco wraps a selection in a language's two comment tokens, so commenting out two statements made a comment that ended at the first statement's own ;. The second statement stayed code, with a stray ; after it. The app now toggles comments itself, using only the language configuration's tokens and the grammar's view of where comments already are. Each statement becomes its own comment, a statement spread over several lines is one comment, and an opener that would land inside a string is refused with a notice naming the line. Ctrl+Shift+/, Sublime Text's block-comment key, came in once the command was right.

Indentation while typing comes from the formatter ADR 0036

Enter after :IF …; left the new line level with the :IF, and :ENDIF; stayed where it was typed. VS Code's usual answer, a pair of patterns, would be a second, weaker account of SSL indentation beside the formatter's. Instead, after Enter the text above is given to the formatter with a probe statement at the end, and wherever the formatter puts the probe is the new line's indentation. Typing the ; of :ENDIF; brings it back out the same way. The answer took 14 ms on a small script. Only leading whitespace changes, and only if the text it was computed for is still there.

A save formats changed lines the way "Format document" would ADR 0037

Format on save asked the server to format only the changed ranges. The server's range format deliberately skips what it does only to whole documents: built-in function casing and blank lines between blocks. So a file saved as formatted changed again under "Format document", for example SqlExecute becoming SQLExecute. A save now formats the whole document and takes just the changed lines from the result, so the two always agree.

SQL data sources are SQL ADR 0038

A .ds file is either SSL or SQL, and its name does not say which; an SQL one may open with a few SSL directives. Every data source opened as SSL. The server's lexical tokens already show what it read as SSL, so whatever stands below that, when it opens with an SQL statement, is now treated as SQL: SQL colours, an SQL outline, and SQL formatting that leaves the directives alone.

Smaller ones

  • A refused rename says so. Renaming to a keyword closed the box, changed nothing and said nothing. It now says the server would not rename it, and that nothing changed.
  • One-line JSON is laid out by "Format document" (ADR 0040). A payload pasted as one line now opens out, while a document that already has lines keeps its layout.

7Keys you can change ADR 0039 · 0041

Settings gained "Editor keys": fifty of the code editor's commands, each with its key on this system, and Set and Clear buttons. A change becomes a rule in the editor's own key list, so its menus and command list show the new key. A desktop self-test caught a subtle bug that the browser hid. Monaco removes a key by rule only if it came with that key, so a cleared Sublime Text key went on working. The fix rebuilds the Sublime Text set without the user's changes each time.

The Markdown Live editor then took the same keys for the thirty-six commands the two editors share, so a change applies in both. Markdown's own keys (bold, italic, link, checkbox and the rest) got their own list in Settings. Before, the editor keys were written in four places that had drifted apart.

8Bringing the parallel work home

Several pieces had been built in side sessions on their own branches. Reconciling them meant three merges, a renumbered ADR (the close work's 0034 became 0042, since the editor work already had a 0034), and adapting tests that had been written against the other branch's behaviour.

  • ClosingClosing keeps unsaved work and asks nothing ADR 0042. As in VS Code, unsaved text is kept in the app's state folder, written within a second of each change, and comes back unsaved when the folder is opened again. Nothing is written into the workspace.
  • Language serverA save does not wait on a silent server. A server that ran but stopped answering kept Ctrl+S from writing the file at all. A save now waits two seconds at most, writes the file as typed, and says so once, with a restart button.
  • Language server"LSP not answering" is one fact, shown everywhere. After five seconds with no answer, the status bar turns red. The outlines, Problems, Procedures, Blocks and the call graph say so instead of "Reading…" forever. A late answer clears it by itself.
  • Narrow windowA question stands over the notices. At 640 wide, a stack of error notices could hide a dialog's buttons. A question, prompt or pick is now drawn above them.
  • Self-testThe long self-test reaches its end and closes by itself, in under a minute.
  • Follow-upA new document's language mode is kept when the window closes, even when the mode was chosen after the last key typed.

9The second review: eight defects

With the merges in, a second adversarial review ran against the real formatters and language server. It found eight defects, all fixed in the app:

  • Markdown formatting changed code samples ADR 0045. Prettier trims every line it prints, so s := "x    in an SSL block lost the spaces in its string. Fenced blocks now keep their trailing spaces wherever nothing else in them changed.
  • Oracle SQL was broken by the default dialect. A .pkb formatted as T-SQL came out as v_due: = SYSDATE. Oracle's files now use Oracle's dialect. Any SQL format that would split :=, <> or a bound :name is refused with a notice.
  • Format Selection on SSL moved a correct line out of its block ADR 0043. Selected lines now come from a format of the whole document, as a save's do.
  • Format Selection did nothing outside SSL. JSON, JavaScript, CSS and the rest now format a selection too.
  • A Windows-1252 file could become UTF-8 ADR 0046. Each save re-guessed the encoding from the bytes on disk. A save now writes the encoding the text was read in.
  • Closing a tab mid-completion raised "Something went wrong" with a stack trace. Completion, rename and the schema hover now stop quietly.
  • The size meter re-read the whole script on the main thread after every pause in typing: 770 ms on a 52,000-line script. It now reads only what changed.
  • Two command palettes became one ADR 0044. Ctrl+Shift+P and F1 open one palette with the app's and the editor's commands, and Ctrl+G opens "Go to line" in the same box.

10Whose bug is it?

The second review had listed several findings as the language server's. That list was challenged: the Markdown item plainly was not the server's responsibility. So each finding was reviewed again, this time against the server's own specification at 0.32.0 rather than against what the IDE would have liked. Three broke a rule the specification states, and were reported upstream:

  • mahoskye/starlims-lsp#378. Rename accepts .T., .F., .AND., .OR. and .NOT. and rewrites every one, although the specification lists them as not renameable.
  • mahoskye/starlims-lsp#379. Signature help and the SQL-placeholder hover count a token's end in bytes against character columns, so a ° or µ in a string shifts them.
  • mahoskye/starlims-lsp#380. Me: inside a class written in the workspace lists none of the class's own members; only the built-in classes are looked up.

The rest were either what the specification asks for or the app's own. One record, ADR 0043, had called the range format's first-line indentation a server defect; the specification calls it intended, and the record now carries a dated correction.

Lesson

Quote the specification's line before calling something a server defect. Keep the app's own findings out of a list addressed to the server.

11The last round: review every area, fix what's broken, add what's missing

The final goal was broader: review each area again, adversarially, fix everything that needed it, and add what was missing. It is commit 86db205.

Formatting says what happened

  • "Format document" on SSL that changed nothing used to say nothing. Now it gives the server's reason when it gave one. Otherwise it says the file has errors that can stop the formatter, or that it is already formatted.
  • A Markdown document whose one code block could not be formatted said "Could not format", though the document had been formatted. It now names the file, says it was formatted, and says which block was not.
  • An SQL data source's formatting error named a line counted from the start of the SQL, not of the file. It now names the line of the file.
  • Indented code blocks (four spaces, no fence) now keep their trailing spaces like fenced ones. Prettier's own Markdown reader finds them.

Finding a procedure by its initials ADR 0047

In VS Code, typing awd finds AddWorkingDays. Here it found nothing: the server matches part of a name only, and its catalog says fuzzy matching is not provided. The app now does the loose matching itself, ranking the way quick open ranks files: the exact name, its start, the starts of its words, anywhere in it, then letters in order.

The first version matched over the server's answer for an empty query. In the example workspace it listed copies of AddWorkingDays from two large generated files and missed the real one in WorkCalendar.ssl. Reading the server's code explained it. The answer stops at 500 symbols, open documents included, and they are drawn from a Go map in no fixed order, so each search sees a different 500. A list that finds some copies of a name and misses others is worse than an empty one.

The rule now: initials are matched only over a list known to be complete. That is the server's full answer when it came back under the cap. Past the cap, it is the open documents' own symbol lists, which the server always gives in full. If nothing matches in a workspace that large, the box says that initials cover only open files and that typing part of the name searches everything. With that, awd puts WorkCalendar.ssl's procedure first, and Enter lands on its :PROCEDURE line.

Indentation you can see and change ADR 0048

The status bar now says "Spaces: 4" or "Tab size: 4", as VS Code does. Its menu offers spaces or tabs, the tab size, converting the file's indentation, and detecting it from the content. A narrow window drops that item, and the line-ends item, from the status bar. The palette had no way to reach either, so it gained "Change Indentation…" and "Change End of Line Sequence…". From the palette, the menu opens at the top of the window, where the palette was.

Typing in a very large script

On a generated 52,680-line script, typing lagged. Measuring long tasks in the page pointed to three causes:

  • The outline worked out which procedure holds the cursor once per row instead of once per cursor move. With 9,200 procedures, that ran 9,200 times on every key.
  • The Agent panel recomputed its context, which scans the whole file, on every key. It now waits for a 250 ms pause.
  • Every key rewrote the document's unsaved flag even when it had not changed, which still woke everything reading it. It is now written only when it changes.

A 6,585-line script now has no long tasks per key at all. On the 52,680-line one, about 40 ms of editor rendering and 45 ms of layout remain per key, most of it from the roughly 18,000 outline rows on the page.

The language server session

  • A document's symbols are now asked for once per version and shared by the outline, breadcrumbs and search, instead of once per asker. The cache clears when the server restarts.
  • Symbol search no longer lists the temporary copies the app has the server read during a format or a check.
  • Findings the server sends for a document after it closed are no longer put back.

Smaller additions

  • Ctrl+. did nothing and said nothing; the server offers no quick fixes. It now says "No code actions available", as VS Code does.
  • Enter after an opening fence in the Live editor opens a line inside and puts the closing fence below it, as Obsidian does. Before, every line after an unclosed fence read as code.
  • A code block's toolbar broke its button names letter by letter in a narrow window. Words now stay whole and wrap as buttons.

The page that scrolled

Opening a status bar menu lifted the whole app 155 pixels, pushing the menu bar off the top and leaving a blank band under the status bar. The cause was a one-pixel line meant for screen readers, inside the outline's "you are here" marker. It was absolutely positioned and escaped the outline's scroll clip, so it sat at y 954 in an 800-pixel window and made the page taller than the window. Any scroll-into-view could then move the page. The scrolling trees now clip what their rows hold, and the page stays exactly the window's height.

A test that read other sessions' work

The documentation-table check timed out because it read every Markdown file under the repository, including 1,919 in old side-session worktrees that git ignores. It now skips those folders, as it already skipped the build and self-test ones, and runs in under two seconds.

12A new language server, 0.33.0

As the last round was committed, starlims-lsp 0.33.0 came out. It answers the rest of a request the IDE had made after the demo project validated clean and then failed to run: three things the server accepted that STARLIMS does not (request L8, mahoskye/starlims-lsp#372). Each was settled by a run on STARLIMS 12:

  • A guard in IIf that guards nothing is a new warning, iif_guard_ineffective. IIf works out both of its value arguments, so IIf(Empty(aDates), CToD(""), aDates[1]) reads aDates[1] even when the list is empty, and raises.
  • A variable from an include, read in a procedure entered by name, gets no rule, by the server's decision D22. A procedure entered by its three-part name reads variables declared anywhere up the call stack, so one call site cannot show whether the name is there.
  • doproc_in_class stands. The sandbox runner had run what STARLIMS refuses to compile.

Four more DoProc shapes, DoProc("Name",) among them, and a quoted :INHERIT parent now fail validation too. Bringing it in meant building 0.33.0 from its tag and pinning it. The demo project stays clean under --validate --strict, and the suites pass on both systems. The IDE keeps no list of diagnostic codes, so the warning needed no code of its own: it shows in the editor and in Problems as the server sends it. Seeing it there turned up two small defects, fixed in commit a36275a:

  • The status bar's Problems item was read out as "0 errors, 1 warnings". It now says "1 warning".
  • In a narrow Problems list, the 21-character code took the whole row and the message had no width at all. Below 420 pixels the code and position now go on a line under the message.

The three defects reported from the second review (#378, #379, #380) are not in this release. They came in 0.33.1 later the same day (section 14).

13Filters out of sight, marks that say what a document is ADR 0049 · 0050 · 0051

With the new server in, the user looked over the rest of the app and asked for six things before any of this was written up for the public. Three were about how the side panels read, one was a defect that made a table hard to use, and two were for the roadmap.

A filter is out of sight until it is asked for

An empty filter box sat at the top of most lists: the Explorer's Outline, the Document panel, Docs, Health, the table view, the list of a schema's uses. Docs and Health also kept a row of filter pills on show, and the plan and the call graph a "Find a step" box that cut the plan's title short. A box nobody is typing in still takes a row and draws the eye.

Now each list's own menu has "Filter…", and Ctrl+F inside the list does the same, as in VS Code's trees. The box opens with the keyboard in it. Left empty, it goes again when the keyboard leaves it, or on Escape, which hands the keyboard back to the list. While it holds text it stays, so what is hiding rows is always in sight. Docs' and Health's pills became ticked items in a funnel menu. A filter that is on shows under the title as a chip that names it and turns it off with a click, and the funnel fills in the accent colour. Search, Reference and the pickers keep their boxes: finding is what they are for. In the table, Ctrl+F stays Find, so the row filter lives in the table's ⋯ menu.

Docs marks a document by its kind

Every Markdown file in the Docs panel had the same mark, so a ticket, a spec, a catalog and a decision looked alike. The panel already knows what each one is, from its folder and its name. Each kind now has its own glyph from the icon set the app already uses: a bulleted list for a catalog, a task list for a ticket, a laid-out sheet for a spec, scales for a decision, a question mark for a question. A robot marks the Agent's instructions, a dashboard the project's state, a table a registry. None of them repeats an activity bar icon, and the colour still follows the file type.

The first choice for a spec was a ruler. Drawn large it read well. At row size it was a thin sliver, so the spec mark changed after a look at the real panel.

A checkbox you can hit

The user said a table's row checkbox was extremely hard to target. Measured, it was 2.6 pixels wide. The selection column was meant to be 56 pixels, but that rule lived in a stylesheet the build places in a chunk that loads before the app's own. An older 32-pixel rule for the same selector won, and the row number squeezed the checkbox to a sliver. The column is now 60 pixels, set in one place. Each checkbox is 16 pixels with a 24-pixel target around it, so a click near the box still ticks it, and Shift still selects a run. A new test fails if an editor's stylesheet sets anything the app's stylesheet sets differently. Putting the old rule back makes it fail.

Trying it by hand turned up a worse problem. Ticking the first row brought a bar of actions in above the table, which pushed every row down about 100 pixels. The next click meant for a checkbox landed on that bar, on its Delete button. The bar now sits under the rows, so ticking a row moves nothing.

Smaller ones

  • The status bar starts with the services: the language server, the Agent, then the Git branch and the Problems counts (ADR 0049).
  • Docs' state dots line up. In a narrow panel the dot for work under way has a ring, which needed 3 pixels each side. The other dots had none, so they sat 3 pixels to the right. All dots now keep that room and share one column.
  • A menu with ticks lines up its words. "Filter…" sat further left than the ticked items below it. Every item in such a menu now keeps the tick's room.
  • On the roadmap: an adversarial review of its own for each panel the editor work did not cover (Explorer, Docs, the Document panel, Palette, Reference, Search, Source control, History, Agent, Health, Output) and for the Settings dialog.

14The three defects, fixed upstream

Later the same day, starlims-lsp 0.33.1 closed all three issues from the second review. Nothing in the IDE had to change, since it applies what the server answers. What changed is how the editor behaves:

  • Rename on .T. now says "Nothing to rename here." Renaming a variable called t edits the variable and leaves every .T. alone.
  • After Left("25 °C", signature help moves to nLength at the comma itself. A SQL placeholder after '°C → µg/L' hovers from its first letter. One on the second line of a multi-line string hovers too, which it never had.
  • Me: in a class of the workspace lists the class's fields and methods. Accepting a method writes its call with the parameters as placeholders: Me:Bump(nBy), with nBy selected.

Six new tests ask the pinned server each case. Run against 0.33.0, every one of them fails, so they will notice if a defect comes back.

15How it was checked

  • Unit tests grew from 3,896 at the start to 4,153 on Linux, with 2 skipped and none failing, and the type check clean throughout. In the Windows 11 VM, at the last commit with 0.33.1 built for Windows, it had 4,121 passing, 35 skipped and none failing.
  • Desktop self-tests (plain, close-and-restore, long cycle) pass on Linux and in the Windows VM, all three with 0.33.1 on both.
  • One Windows-only failure turned up on the way: a closing test that opens a folder, and so starts the language server, took 5.3 seconds under the whole suite against a 5-second limit. It passed three times out of three on its own, and its limit is now 30 seconds.
  • In the running app, each visible change was looked at 720 and 1400 wide, light and dark, by real clicks and keys where the browser tool can send them, and by dispatched key events where it cannot.

16What is still open

  • Initials in a large workspace cover open files only. If the server ever matches letters in order itself, as the protocol suggests for workspace/symbol, that limit goes away with no change here.
  • Typing in a 50,000-line script still costs about 85 ms per key, most of it from the outline's many rows.
  • Not tried on a Mac. Sublime Text's Mac keys are set, but no one has pressed them.
  • The panels and the Settings dialog have not had a review of their own yet. They are on the roadmap.
